# DeepSeek 模型选择控件设计

## 问题与根因

当前模型字段使用 `input[list] + datalist`。Chromium 会按输入框现有文本过滤 `datalist` 候选；设置加载后输入框已经包含 `deepseek-v4-pro`，因此展开候选时只显示该精确匹配项，虽然 HTML 中还存在 `deepseek-v4-flash`。

## 目标

- 官方模型选项始终完整可见。
- 当前提供 `deepseek-v4-pro` 和 `deepseek-v4-flash`。
- 保留自定义 Base URL 对应自定义模型名称的能力。
- 已保存的自定义模型能正确回显、编辑和再次保存。
- 不改变配置文件和主进程模型 provider 的数据结构。

## 界面设计

将模型输入框改为原生 `select`：

- `deepseek-v4-pro`
- `deepseek-v4-flash`
- `自定义模型...`

选择“自定义模型...”时显示独立文本输入框；选择官方模型时隐藏该输入框。原生 `select` 不会按当前值过滤选项，并具备稳定的键盘和辅助功能行为。

## 数据转换

在现有 `src/renderer/view-model.ts` 中增加纯函数，不创建新模块：

- 从已保存模型名称生成 `{ preset, custom }` 表单状态。
- 从 `{ preset, custom }` 生成提交给 IPC 的最终模型名称。

官方名称映射到对应下拉值。未知名称映射到“自定义模型”并原样放入自定义输入框。DeepSeek 模式选择自定义项时，输入框动态设为必填并使用浏览器原生字段校验；切换到 Codex 后取消必填，空的隐藏字段回退到当前已保存模型，不能阻止 Codex 设置保存。主进程仍保留“模型名称不能为空”的最终边界校验。

## 测试

- 纯函数测试覆盖两个官方模型、自定义模型回显和自定义值提交。
- 设置弹窗结构测试确认使用 `select`、三个选项和自定义输入框，不再使用 `datalist`。
- 绑定测试确认加载、切换和保存都调用纯转换逻辑。
- 完成类型检查、全量测试和生产构建。
